System Architecture

The tool follows a linear pipeline architecture. All processing is local — no external APIs, cloud services, or databases are used.

ℹ️
Fully local execution. The tool reads from Outlook on the local machine and sends via the local Outlook profile. No data leaves the corporate environment through any external service.

Data Flow & Execution Pipeline

1
Connect to Outlook
connect_outlook() → returns MAPI namespace via COM. Fails with sys.exit(1) if Outlook is not open.
2
Open Monitoring Folder
get_folder(namespace, folder_name) → Outlook folder object. Raises FileNotFoundError if folder not found.
3
Fetch & Deduplicate Emails
get_emails_by_subject(folder, MONITORING_KEYWORDS, days_back) → raw email list. Then deduplicate_latest() removes older duplicates. Returns list[dict] with keys: subject, received_time, sender, body.
4
Parse Monitoring Data
parse_monitoring_emails(emails) → MonitoringData object with .tablespaces, .diskgroups, .mount_points lists.
5
Build HTML Dashboard
build_html(data, report_date, emails) → complete HTML string. Groups data by environment then database. Renders critical alerts, three typed tables, summary cards.
6
Save HTML File
Written to <script_dir>/monitoring_dashboard_YYYYMMDD.html using UTF-8 encoding.
7
Open in Browser
webbrowser.open(file:///path) — skipped if --no-browser flag is set.
8
Send Email with Attachment
Sends to all recipients in {send_to, RECIPIENT_EMAIL} deduplicated set. Each email has full HTML body + .html file attached via Outlook COM.

Alert & Status Logic

The critical alert section collects items using nested defaultdict structures and renders them in type → environment → database order.

# Three nested dicts collect critical items
crit_ts = defaultdict(lambda: defaultdict(list))  # env → db → [ts]
crit_dg = defaultdict(lambda: defaultdict(list))  # env → db → [dg]
crit_mp = defaultdict(lambda: defaultdict(list))  # env → host → [mp]

for ts in _dedupe(data.tablespaces, ...):
    if ts.used_percent >= TS_CRIT:
        crit_ts[_env(ts.database)][ts.database].append(ts)

Deduplication Logic

Two independent deduplication passes run at different stages of the pipeline:

Level 1 — Email Deduplication
Function: deduplicate_latest()

Sorts emails by received_time descending. Normalises subject via _normalize() (strips dates). Keeps only the most recent email per normalised subject.

Prevents: old/duplicate monitoring emails inflating data.
Level 2 — Entry Deduplication
Function: _dedupe(entries, key)

Sorts entries by used_percent descending. Keeps the entry with the highest usage for each unique key.

Prevents: same tablespace/diskgroup/mountpoint appearing multiple times if it appeared in multiple emails.

Email Delivery — Outlook COM

# COM object chain in _send_with_attachment()
outlook = win32com.Dispatch("outlook.application")
mail    = outlook.CreateItem(0)        # 0 = olMailItem

mail.To       = to_addr
mail.Subject  = f"📊 {day_name} Monitoring Dashboard ({report_date})"
mail.HTMLBody = html_body              # full colour-coded HTML
mail.Attachments.Add(abs_path)       # .html file attached
mail.Send()

Recipient Resolution

# Deduplicates recipients — sends to both if different addresses
recipients = list({r for r in [send_to, RECIPIENT_EMAIL] if r and "@" in r})
⚠️
Prerequisite: Outlook must be open and a mail profile must be configured. If pywin32 is not installed, a RuntimeError is raised, caught, and printed — the script continues without sending.

Inter-Module Interface Contract

outlook_reader.py — Required Functions

connect_outlook() → namespace
    # Returns win32com MAPI namespace. Raises exception if Outlook unavailable.

get_folder(namespace, folder_name: str) → folder_object
    # folder_object must support: .Name (str), .Items.Count (int)
    # Must raise FileNotFoundError if folder not found

get_emails_by_subject(folder, keywords: list, days_back: int) → list[dict]
    # Each dict: { 'subject': str, 'received_time': datetime,
    #               'sender': str, 'body': str }

email_parser.py — Required Function

parse_monitoring_emails(emails: list) → MonitoringData

# MonitoringData must expose:
.tablespaces   # list of objects with: .database, .tablespace_name, .used_percent
.diskgroups    # list of objects with: .database, .diskgroup_name,  .used_percent
.mount_points  # list of objects with: .host, .mount_point,          .used_percent
ℹ️
Note: The host field on mount_point objects may be empty or None. The dashboard handles this by falling back to "Unknown Host" as the sub-group label.

Extensibility Guide

Add a New Environment Type

# 1. Add check in _env() before the final return "OTHER":
if "STG" in t or "STAGE" in t: return "STAGE"

# 2. Add colour to ENV_COLORS dict:
ENV_COLORS["STAGE"] = "#f39c12"

# 3. Add to env_order in build_html():
env_order = ["PROD", "QA/QTS", "TST", "STAGE", "DEV", "OTHER"]

Schedule Weekly Automated Run (Windows Task Scheduler)

# Action: Start a program
Program:   python
Arguments: C:\monitoring-tool\dashboard.py
Trigger:   Weekly, Friday, 08:00 AM
Run as:    User with Outlook logged in
✅
Tip: Add --no-browser to the Task Scheduler arguments so no browser window opens during unattended runs. The email will still be sent automatically.

Known Limitations

1Windows-only (win32com / COM)Cannot run on Linux or macOS without replacing Outlook integration
2Outlook must be openCannot run as a background service or headless task without Outlook active

Glossary

TermDefinition
ASMAutomatic Storage Management — Oracle's volume manager. Diskgroups are ASM storage units.
COM / MAPIWindows-native APIs used to interact with Outlook programmatically via win32com.
DiskgroupAn Oracle ASM logical pool of disk storage. Critical for preventing Oracle outages.
Mount PointA Linux/Unix directory at which a storage volume is attached (e.g. /u01, /data).
TablespaceA logical Oracle DB storage unit. Usage % = how much of allocated space is consumed.
used_percentPercentage of allocated capacity currently in use for any monitored resource.
olMailItemOutlook COM constant (value = 0) representing a mail message, used in CreateItem(0).
pywin32Python package providing Windows COM and Win32 API access. Install: pip install pywin32.
defaultdictPython collections class that auto-creates default values for missing keys, used for grouping without KeyError.
MonitoringDataObject returned by email_parser.py containing parsed tablespace, diskgroup, and mount point lists.
